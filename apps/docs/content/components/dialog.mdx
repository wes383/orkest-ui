`Dialog` is a modal surface for content that temporarily takes over the page context. Use it for
editing, creating, viewing details, authentication, and complex forms.

The component is built on Base UI Dialog and exported from `@orkest/ui/client`.

## Basic usage

<ComponentPreview
  title="Edit profile"
  code={`import { Button, Stack } from '@orkest/ui';
import {
  Dialog,
  DialogBody,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogOverlay,
  DialogPortal,
  DialogTitle,
  DialogTrigger,
  Field,
  FieldLabel,
  Input,
} from '@orkest/ui/client';

export function Example() {
  return (
    <Dialog>
      <DialogTrigger>Edit profile</DialogTrigger>
      <DialogPortal>
        <DialogOverlay />
        <DialogContent>
          <DialogHeader>
            <DialogTitle>Edit profile</DialogTitle>
            <DialogDescription>
              Update the name and email shown on your account.
            </DialogDescription>
          </DialogHeader>
          <DialogBody>
            <Stack gap={4}>
              <Field>
                <FieldLabel>Display name</FieldLabel>
                <Input defaultValue="Ada Lovelace" />
              </Field>
              <Field>
                <FieldLabel>Email</FieldLabel>
                <Input type="email" defaultValue="ada@example.com" />
              </Field>
            </Stack>
          </DialogBody>
          <DialogFooter>
            <DialogClose>Cancel</DialogClose>
            <DialogClose render={<Button>Save changes</Button>} />
          </DialogFooter>
        </DialogContent>
      </DialogPortal>
    </Dialog>
  );
}`}

</ComponentPreview>

## Anatomy

- `Dialog` owns the open state and modal behavior.
- `DialogTrigger` opens the dialog. It renders a primary Button by default.
- `DialogPortal` moves the dialog to the document body.
- `DialogOverlay` renders the backdrop.
- `DialogContent` centers the dialog, limits its height, and can render the built-in close action.
- `DialogHeader` groups `DialogTitle` and `DialogDescription`.
- `DialogBody` scrolls when the content exceeds the available height.
- `DialogFooter` aligns the actions.
- `DialogClose` closes the dialog and renders a secondary Button by default.

Compose `DialogTrigger` and `DialogClose` with `render` when you need a different Button variant or a
custom element.

## Sizes

`DialogContent` supports `sm`, `md`, `lg`, `xl`, and `full`. The viewport keeps a safe gutter and the
surface shrinks to the available width on small screens.

<ComponentPreview
  title="Size presets"
  code={`import { Box, Stack } from '@orkest/ui';
import {
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogOverlay,
  DialogPortal,
  DialogTitle,
  DialogTrigger,
} from '@orkest/ui/client';

const sizes = ['sm', 'md', 'lg', 'xl', 'full'] as const;

export function Example() {
  return (
    <Box width="100%" maxWidth="30rem">
      <Stack direction="row" gap={2} wrap>
        {sizes.map((size) => (

            <DialogTrigger variant="outline">{size}</DialogTrigger>
            <DialogPortal>

                  <DialogTitle>{size} dialog</DialogTitle>

                    Resize the viewport to see the responsive constraints.
                  </DialogDescription>
                </DialogHeader>
                <DialogFooter>
                  <DialogClose>Close</DialogClose>
                </DialogFooter>
              </DialogContent>
            </DialogPortal>
          </Dialog>
        ))}
      </Stack>
    </Box>
  );
}`}

## Scrolling content

Use `DialogBody` for content that can grow. The header and footer stay visible while the body
scrolls.

<ComponentPreview
  title="Scrollable dialog"
  code={`import { Stack, Text } from '@orkest/ui';
import {
  Dialog,
  DialogBody,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogOverlay,
  DialogPortal,
  DialogTitle,
  DialogTrigger,
} from '@orkest/ui/client';

const clauses = Array.from(
  { length: 40 },
  (_, index) =>
    \`Clause \${index + 1}. This section is long enough to demonstrate a scrollable dialog body while the header and footer stay visible. It includes additional wording so the example overflows on large screens as well.\`,
);

export function Example() {
  return (
    <Dialog>
      <DialogTrigger variant="secondary">View terms</DialogTrigger>
      <DialogPortal>
        <DialogOverlay />
        <DialogContent size="lg">
          <DialogHeader>
            <DialogTitle>Service terms</DialogTitle>
            <DialogDescription>
              Review the full text before accepting.
            </DialogDescription>
          </DialogHeader>
          <DialogBody>
            <Stack gap={3}>
              {clauses.map((clause) => (
                <Text key={clause} as="p" size="sm" tone="muted">
                  {clause}
                </Text>

            </Stack>
          </DialogBody>
          <DialogFooter>
            <DialogClose>Close</DialogClose>
          </DialogFooter>
        </DialogContent>
      </DialogPortal>
    </Dialog>
  );

## Close behavior

`Dialog` closes on Escape and overlay press by default. Disable either path when the content should
not be dismissed accidentally:

```tsx
<Dialog closeOnEscape={false} closeOnOverlayClick={false}>
```

`DialogContent` renders an icon close action by default. Use `showCloseButton={false}` to hide it,
or `closeLabel` to change its accessible name.

## Accessibility

- Render `DialogTitle` for the accessible name and `DialogDescription` for supporting text. Base UI
  wires `aria-labelledby` and `aria-describedby` automatically.
- Modal dialogs trap focus, lock page scroll, and restore focus to the trigger or the previously
  focused element when closed.
- Use `initialFocus` to focus a specific field when the dialog opens.
- Escape and overlay press close the dialog by default. Disable them only when the task must not be
  dismissed accidentally.
- The built-in close action is a labeled button (`closeLabel`). Provide an accessible name when
  composing `DialogClose` with a custom icon button.
- Use `DialogBody` for long content so the header and footer remain reachable.
- `full` dialogs keep the same focus and keyboard behavior as smaller sizes.
