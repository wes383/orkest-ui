`Combobox` is an input combined with a list of predefined options. Typing filters the list, and the
choice is written back into the field. It only ever commits values that exist in `options`; for free
text with suggestions, use an autocomplete pattern instead.

Import it from `@orkest/ui/client`.

## Live preview

import { Combobox } from '@orkest/ui/client';

const fruits = [

{ value: 'grape', label: 'Grape' },
{ value: 'mango', label: 'Mango' },

return (

      clearable
      placeholder="Pick a fruit"

}`;

## When to use it

| Component     | Use it for                                             |
| ------------- | ------------------------------------------------------ |
| `Select`      | Choosing from a short, fixed list with no search.      |
| `Combobox`    | Searching a long list and choosing exactly one option. |
| `MultiSelect` | Searching a long list and choosing several options.    |

`Combobox` always renders an input. Opening the field starts a fresh search, so a new query never
needs the old label deleted first; closing it puts the chosen label back.

## Controlled and uncontrolled

Pass `value` and `onChange` to control the selection, or `defaultValue` to start uncontrolled. The
value is the option's `value`, so keep it to a stable ID when the options come from a database:

```tsx
<Combobox
  aria-label="Assignee"
  options={users.map((user) => ({ value: user.id, label: user.name }))}
  value={assigneeId}
  onChange={(next, option) => {
    setAssigneeId(next);
    // `option` carries the row that produced the value: description, icon, and so on.
    console.log(option?.description);
  }}
/>
```

`onChange` receives `null` when the field is cleared, either from the clear action or by deleting
the text and confirming.

## Groups

Options can be interleaved with `{ label, options }` groups. The group label is announced with the
listbox and is not selectable itself.

export const groupedOptionsCode = `import { Combobox } from '@orkest/ui/client';

const projects = [
{
label: 'Engineering',
options: [
{ value: 'frontend', label: 'Frontend', description: 'Web interfaces' },
{ value: 'backend', label: 'Backend', description: 'APIs and services' },
],
},
{
label: 'Marketing',
options: [{ value: 'website', label: 'Website', description: 'Public site' }],
},
];

export function Example() {
  return (
    <Combobox
      aria-label="Project"
      options={projects}
      defaultValue="backend"
      placeholder="Pick a project"

  );
}`;

## Custom option content

`renderItem` replaces the label / description block. The row still gets the selected state, the
check indicator, and keyboard highlighting from the listbox:

export const customRowsCode = `import { Combobox } from '@orkest/ui/client';

export function Example() {
  return (
    <Combobox
      aria-label="Project"
      options={projects}
      defaultValue="frontend"
      renderItem={(option) => (
        <span style={{ display: 'grid', gap: 2 }}>
          <strong>{option.label}</strong>
          <small>{option.description}</small>
        </span>
      )}
    />
  );
}`;

## Async search and loading

For a server-backed list, filter nothing locally and let the options be the response. Pass
`filterOption={null}` to switch the local matcher off, use `onSearchChange` to fire the request, and
`loading` to show the status row:

```tsx
const [query, setQuery] = useState('');
const [options, setOptions] = useState<SelectOption[]>([]);
const [loading, setLoading] = useState(false);

<Combobox
  aria-label="Country"
  options={options}
  filterOption={null}
  loading={loading}
  onSearchChange={async (next) => {
    setQuery(next);
    setLoading(true);
    setOptions(await searchCountries(next));
    setLoading(false);
  }}
  emptyMessage="No country matched"
/>;
```

export const serverSideSearchCode = `<Combobox
  aria-label="Country"
  options={results}
  filterOption={null}
  loading={loading}
  onSearchChange={setQuery}
  placeholder="Pick a country"
  emptyMessage="No country matched"
/>`;

While `loading` is set, the rows are replaced by the status row: the rows on screen still belong to
the previous query, so they step aside instead of sitting under the spinner. The listbox keeps its
`aria-busy="true"` and the status row is announced politely. Options that arrive with the next
response are rendered as soon as `loading` goes back to `false`.

## Accessibility

- The input is the combobox: it exposes `aria-expanded`, `aria-controls`, and `aria-autocomplete`,
  and the popup is a `listbox` of `option` rows. Group labels are `group` names.
- Typing filters and highlights the first match; `ArrowDown` / `ArrowUp` move the highlight, `Enter`
  commits, `Escape` closes and restores the chosen label.
- Opening starts an empty query, so the first keystroke is never appended to the previous label.
- Disabled rows are skipped by the keyboard and expose `aria-disabled="true"`.
- `name` and `required` are forwarded to the hidden input Base UI renders, so the field submits with
  the surrounding form.
- With `loading`, the status row is a polite live region and the listbox is marked busy.
