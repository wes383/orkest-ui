`Alert Dialog` interrupts the user only when a decision is required. Use it for destructive or
irreversible actions such as deleting data, discarding changes, resetting state, or signing out.

It is built on Base UI Alert Dialog and exported from `@orkest/ui/client`.

## Dialog vs Alert Dialog

| Behavior                    | Dialog             | Alert Dialog           |
| --------------------------- | ------------------ | ---------------------- |
| Overlay press closes        | Yes by default     | No                     |
| Escape closes               | Yes by default     | No                     |
| Focus management            | Yes                | Yes                    |
| Requires an explicit choice | No                 | Yes                    |
| Typical use                 | Edit, view, create | Delete, discard, reset |

Alert Dialog does not render a built-in close icon. The only ways out are the cancel and confirming
actions.

## Basic usage

export const deleteConfirmationCode = `import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogOverlay,
  AlertDialogPortal,
  AlertDialogTitle,
  AlertDialogTrigger,
} from '@orkest/ui/client';

export function Example() {
  return (
    <AlertDialog>
      <AlertDialogTrigger variant="destructive">Delete project</AlertDialogTrigger>
      <AlertDialogPortal>
        <AlertDialogOverlay />
        <AlertDialogContent>
          <AlertDialogHeader>
            <AlertDialogTitle>Delete project?</AlertDialogTitle>
            <AlertDialogDescription>
              This permanently deletes the project and its data. This action cannot be undone.
            </AlertDialogDescription>
          </AlertDialogHeader>
          <AlertDialogFooter>
            <AlertDialogCancel>Cancel</AlertDialogCancel>
            <AlertDialogAction>Delete project</AlertDialogAction>
          </AlertDialogFooter>
        </AlertDialogContent>
      </AlertDialogPortal>
    </AlertDialog>
  );
}`;

<ComponentPreview title="Delete confirmation" code={deleteConfirmationCode}>

</ComponentPreview>

`AlertDialogCancel` renders a secondary Button. `AlertDialogAction` renders a destructive Button.
Both actions close the dialog.

## Async actions

For an action that must finish before closing, control the dialog and use a regular Button with a
loading state. The dialog stays open until the request succeeds.

export const asyncConfirmationCode = `import { useState } from 'react';
import { Button } from '@orkest/ui';
import {
  AlertDialog,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogOverlay,
  AlertDialogPortal,
  AlertDialogTitle,
} from '@orkest/ui/client';

export function Example() {
  const [open, setOpen] = useState(false);
  const [loading, setLoading] = useState(false);

  async function handleDelete() {
    setLoading(true);
    await new Promise((resolve) => setTimeout(resolve, 600));
    setLoading(false);
    setOpen(false);
  }

  return (
    <>
      <Button variant="destructive" onClick={() => setOpen(true)}>
        Delete account
      </Button>
      <AlertDialog open={open} onOpenChange={setOpen}>
        <AlertDialogPortal>
          <AlertDialogOverlay />
          <AlertDialogContent>
            <AlertDialogHeader>
              <AlertDialogTitle>Delete account?</AlertDialogTitle>
              <AlertDialogDescription>
                All projects and data will be removed. This action cannot be undone.
              </AlertDialogDescription>
            </AlertDialogHeader>
            <AlertDialogFooter>
              <AlertDialogCancel disabled={loading}>Cancel</AlertDialogCancel>
              <Button variant="destructive" loading={loading} onClick={handleDelete}>
                Delete account
              </Button>
            </AlertDialogFooter>
          </AlertDialogContent>
        </AlertDialogPortal>
      </AlertDialog>
    </>
  );
}`;

  <AlertDialogControlledExample />
</ComponentPreview>

## Accessibility

- Always render `AlertDialogTitle` and `AlertDialogDescription`. The description should state the
  consequence, not just repeat the title.
- Focus moves into the dialog when it opens and returns to the trigger when it closes.
- Escape and overlay press do not close the dialog. This is enforced by the component.
- The cancel action receives initial focus by default, reducing the chance of accidental
  confirmation.
- `AlertDialogAction` closes the dialog immediately. For async work, use a controlled dialog and a
  regular Button with a loading state.
- Do not use Alert Dialog for non-blocking messages. Use Dialog or inline feedback instead.
