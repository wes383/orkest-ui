`Pagination` splits a long collection into pages. It is controlled: you own the current page, it
reports the page the reader asked for. Page numbers, clamping, and ellipsis handling are computed for
you, and the same markup is available piece by piece when the shape needs to differ.

It renders buttons, which is what client-side paging wants. A link-based variant for
server-rendered search results, where every page needs a real URL, is a separate concern and is not
part of this component.

`md` is the default. All three sizes share the same footprint rules, so switching size never changes
how many pages fit before the list wraps.

With a large page count the list keeps the boundary pages and a window around the current page,
collapsing everything else into a single ellipsis per side. `siblingCount` controls the window — `1`
shows one page on each side of the current one, `2` shows two.

First and last jumps are off by default; a long list only gets them when you ask for them:

<ComponentPreview
  title="First and last jumps"

}`}

The range is also exported, so a custom layout can reuse the same rules:

```tsx
import { getPaginationRange } from '@orkest/ui';

getPaginationRange(10, 20); // [1, 'start-ellipsis', 9, 10, 11, 'end-ellipsis', 20]
```

## Composition

When the default list is not the right shape, pass the parts as children. `Pagination` keeps the
`nav` landmark, the accessible name, and the size; the children decide the layout:

```tsx
import {
  Pagination,
  PaginationContent,
  PaginationEllipsis,
  PaginationItem,
  PaginationLink,
  PaginationNext,
  PaginationPrevious,
} from '@orkest/ui';

<Pagination page={page} totalPages={20} onPageChange={setPage} label="Search results">
  <PaginationContent>
    <PaginationItem>
      <PaginationPrevious label="Previous" disabled={page === 1} onClick={() => setPage(page - 1)} />
    </PaginationItem>
    <PaginationItem>
      <PaginationLink page={1} isActive={page === 1} onClick={() => setPage(1)} />
    </PaginationItem>
    <PaginationEllipsis />
    <PaginationItem>
      <PaginationLink page={20} isActive={page === 20} onClick={() => setPage(20)} />
    </PaginationItem>
    <PaginationItem>
      <PaginationNext label="Next" disabled={page === 20} onClick={() => setPage(page + 1)} />
    </PaginationItem>
  </PaginationContent>
</Pagination>;
```

## Boundary rules

- A `page` below `1` or above `totalPages` is clamped before rendering, so an out-of-range value can
  never produce a state the reader cannot leave.
- Previous and next are disabled with the native `disabled` attribute at the ends of the range, not
  hidden.
- `totalPages` of `0` renders nothing at all: an empty collection has no pages to navigate.
- A single page also renders nothing, because the control would have nothing to do.
- Clicking the page you are already on does not call `onPageChange`.
- An ellipsis is decoration with an accessible label. It is never focusable and never clickable.

## Accessibility

- The wrapper is `<nav aria-label="Pagination">`; rename it with `label` when a page has more than one
  paginator.
- The current page carries `aria-current="page"` and a border plus background, so the state is not
  communicated by color alone.
- Chevron-only controls have accessible names through `previousLabel`, `nextLabel`, `firstLabel`, and
  `lastLabel`.
- Everything is a real `button`, so Tab order, Enter, and Space work without extra handlers.
- The visual dots are hidden from assistive technology and replaced by the `More pages` text, so the
  skip is announced once and not as punctuation.
