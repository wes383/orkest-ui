title: Date Picker
description: Pick a calendar date from a popover calendar, with typed formatting and range limits.

`DatePicker` pairs a field with a [Calendar](/docs/components/calendar/) in a popover. The value is a
`YYYY-MM-DD` string, never a `Date`, so it survives a round trip through a database or an API without
a timezone shifting it by a day.

The field is a button, not a text input: typing a date in six different formats is a worse experience
than picking it from a grid, and it removes a whole class of parsing bugs.

export function Example() {

Selecting a day commits the value and closes the popover. The footer keeps `Today` and `Clear` within
reach; `Today` is disabled when it falls outside the allowed range.

## Range limits

<ComponentPreview
  title="Bounded range"
  code={`import { useState } from 'react';
import { DatePicker } from '@orkest/ui/client';

export function Example() {
  const [value, setValue] = useState<string | null>('2026-11-18');

  return (
    <DatePicker
      value={value}
      onChange={setValue}
      minDate="2026-11-10"
      maxDate="2026-12-20"
      disabledDates={(date) => date.endsWith('-15') || date.endsWith('-16')}
    />
  );
}`}
>
  <DatePickerRangeExample />
</ComponentPreview>

`minDate`, `maxDate`, and `disabledDates` are passed straight to the calendar, so the popover opens on a
navigable month and blocked days stay visible but inert.

## Display format

`format` accepts an `Intl.DateTimeFormat` date style. Pass a function when the exact string matters —
an ISO value, a custom suffix, a label from your own i18n bundle.

<ComponentPreview
  title="Custom and localized formats"
  code={`import { useState } from 'react';
import { Stack } from '@orkest/ui';
import { DatePicker } from '@orkest/ui/client';

export function Example() {
  const [value, setValue] = useState<string | null>('2026-11-18');

  return (
    <Stack gap={3}>
      <DatePicker
        value={value}
        onChange={setValue}
        format={(iso) => iso.replaceAll('-', '/')}
      />
      <DatePicker value={value} onChange={setValue} locale="en-GB" format="full" />
    </Stack>
  );
}`}
>
  <DatePickerFormatExample />
</ComponentPreview>

The format only affects the field text. `onChange` always reports `YYYY-MM-DD`.

## Inside a Field

`DatePicker` reads the surrounding [Field](/docs/components/field/) context: the label points at the
trigger, `aria-describedby` carries the description and validation message, and `required` and
`invalid` follow the field.

<ComponentPreview
  title="With a label and description"
  code={`import { useState } from 'react';
import { Field, FieldDescription, FieldLabel, DatePicker } from '@orkest/ui/client';

export function Example() {
  const [value, setValue] = useState<string | null>(null);

  return (
    <Field required>
      <FieldLabel>Start date</FieldLabel>
      <DatePicker value={value} onChange={setValue} placeholder="Choose a start date" />
      <FieldDescription>Leave empty to start immediately.</FieldDescription>
    </Field>
  );
}`}
>
  <DatePickerFieldExample />
</ComponentPreview>

Passing `name` also renders a hidden input, so the value is submitted with a native form.

## Desktop and mobile

The same popover is used at every width. It is positioned against the trigger, stays inside the
viewport, and the calendar cells are comfortably above the minimum touch target, so it does not need a
separate bottom-sheet implementation.

When you do want a full-screen sheet, compose the parts yourself: `Calendar` is exported on its own
and works inside any [Dialog](/docs/components/dialog/).

## Accessibility

- The trigger is a button with `aria-haspopup="dialog"` and `aria-expanded`, so the popup is announced
  before it opens.
- `Enter` or `Space` opens the calendar; focus moves into the grid; `Escape` closes it and returns focus
  to the trigger.
- The grid is a single tab stop with full arrow-key navigation, described in the
  [Calendar documentation](/docs/components/calendar/#accessibility).
- The clear action has its own accessible name and never sits inside the trigger, so it stays a
  separate, reachable target.
