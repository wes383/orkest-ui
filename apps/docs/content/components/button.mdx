`Button` renders a native `<button>` with a small set of visual variants, four sizes, optional icons,
and a loading state. It defaults to `type="button"` so it does not submit a form accidentally.

Use `Button` for actions. For navigation, render a link element instead. For icon-only actions, use
[IconButton](/docs/components/icon-button/) which requires an accessible name.

## Icons

Icons are decorative because the button label supplies the accessible name. The icon size follows the
button size.

required and becomes the accessible name.

    <Button loading>Saving</Button>
    <Button variant="outline" loading>
      Publishing
    </Button>
  </Stack>

`loading` sets the native `disabled` attribute, exposes `aria-busy="true"`, and replaces the leading
icon with a spinner. This blocks repeated submissions but also removes the button from the tab order
until loading completes.

## Accessibility

- `Button` renders a native `<button>`, so Enter and Space activate it.
- The default `type` is `button`. Set `type="submit"` explicitly for form submission.
- Loading buttons are natively disabled and announce `aria-busy`. The label remains available to
  assistive technology.
- Leading and trailing icons are hidden from assistive technology. The label supplies the accessible
  name.
- `iconOnly` requires an `aria-label`. Prefer `IconButton`, whose `label` prop is required.
- The focus-visible ring uses the shared focus tokens and is not removed.
- Disabled buttons rely on the native disabled state and a muted token surface, not color alone.
- The link variant does not change semantics; use an anchor for navigation.
