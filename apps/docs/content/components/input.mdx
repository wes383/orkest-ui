`Input` renders a native `<input>` inside a token-styled field. It supports four sizes, leading and
trailing icons, invalid, disabled, and read-only states, and fills the width of its container.

`Input` is exported from `@orkest/ui/client`. Render it inside a Client Component.

Pair it with [Label](/docs/components/typography/#semantic-components) for the accessible name and
[Caption](/docs/components/typography/) for help text.

## Types

`Input` forwards the native `type` attribute, so common HTML input types work without extra props:

- `text` — plain text
- `email` — email addresses
- `password` — masked text
- `number` — numeric input
- `search` — search fields
- `tel` — telephone numbers
- `url` — URLs
- `date` — dates
- `time` — times
- `datetime-local` — dates and times

Native browser validation, autocomplete, and input modes remain available.

## Actions

`clearable` shows a clear action while the input has a value. `passwordToggle` adds a visibility
toggle for password fields. Both actions have accessible names and keep focus inside the field.

## Accessibility

- Provide an accessible name with `Label htmlFor` or `aria-label`. A placeholder is not a label.
- Connect help and error text with `aria-describedby`.
- `invalid` sets `aria-invalid`. Pair it with visible error text; do not rely on the border color
  alone.
- `disabled` and `readOnly` use the native attributes and remain distinguishable without color alone.
- Leading and trailing icons are decorative and hidden from assistive technology.
- Clear and password actions are buttons with accessible names. The password toggle exposes
  `aria-pressed`.
- With a controlled `value`, update it in `onChange` when the clear action fires.
- The character count is supplementary. `maxLength` remains the native constraint.
- Refs are forwarded to the native input element.
