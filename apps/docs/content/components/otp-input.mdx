`OTPInput` renders one input slot per digit. It supports controlled and uncontrolled values,
masked entry, validation, completion callbacks, and form submission through Base UI OTP Field.

`OTPInput` is exported from `@orkest/ui/client`.

## Basic usage

export const otpInputBasicCode = `import { OTPInput } from '@orkest/ui/client';

export function Example() {
  return (
    <OTPInput
      aria-label="Verification code"
      length={6}
      separator={<span aria-hidden="true">·</span>}
    />
  );
}`;

`length` is required and must match the number of slots you expect the user to fill.

## Masked and controlled

Pass `mask` to render password inputs. Use `value` and `onValueChange` to keep the code in your own
state, and `onValueComplete` to react when every slot is filled.

export const otpInputMaskedCode = `import { useState } from 'react';
import { Stack, Text } from '@orkest/ui';
import { OTPInput } from '@orkest/ui/client';

export function Example() {
  const [value, setValue] = useState('');
  const [complete, setComplete] = useState(false);

  return (
    <Stack gap={2}>
      <OTPInput
        aria-label="One-time password"
        length={6}
        mask
        value={value}
        onValueChange={(nextValue) => {
          setValue(nextValue);
          setComplete(false);
        }}
        onValueComplete={() => setComplete(true)}
      />
      <Text size="sm" tone="muted">
        {complete ? 'Code complete.' : \`\${value.length} of 6 digits entered.\`}
      </Text>
    </Stack>
  );
}`;

</ComponentPreview>

## Separators

Set `separator` to render content between groups of three slots. No separator is rendered after the
final slot, so a six-digit code shows one separator and a nine-digit code shows two. The example
above uses a centered dot between the two groups.

## Sizes

`size` accepts `sm`, `md`, and `lg`. Slots stay square at every size, and the text scales with the
slot.

## States

- `disabled` disables every slot and dims the surface.
- `readOnly` keeps the value visible and focusable while preventing edits.
- Wrap the field in `Field` to show validation messages; the invalid state is reflected on the
  group and its slots.
- `required`, `name`, and `autoSubmit` integrate with native forms.

## Keyboard interaction

| Key                    | Behavior                              |
| ---------------------- | ------------------------------------- |
| ArrowLeft / ArrowRight | Move focus between slots              |
| Backspace / Delete     | Clear the current or previous slot    |
| Home / End             | Move focus to the first or last slot  |
| Paste                  | Fill the remaining slots from the text |
| Tab                    | Move focus into or out of the field   |

## Accessibility

- The root renders `role="group"`. Give it an accessible name with `aria-label` or
  `aria-labelledby`, or use `FieldLabel` inside `Field`.
- Each slot is a native input, so keyboard and screen-reader behavior follow the platform.
- `mask` renders password inputs without exposing the entered digits visually.
- Disabled, read-only, and invalid states use native attributes and are exposed to assistive
  technology.
- Focus is always visible through the shared focus ring token.
- Motion respects `prefers-reduced-motion`.
