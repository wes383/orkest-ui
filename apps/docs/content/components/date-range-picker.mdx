`DateRangePicker` is a [Calendar](/docs/components/calendar/) pair behind a single field. The value is
a plain object of two `YYYY-MM-DD` strings, so it survives a round trip through a database or an API
without a timezone shifting either end.

## Live preview

export const basicDateRangePickerCode = `import { useState } from 'react';
import { Stack, Text } from '@orkest/ui';
import { DateRangePicker } from '@orkest/ui/client';
import type { DateRange } from '@orkest/ui/client';

export function Example() {
  const [value, setValue] = useState<DateRange | null>({
    start: '2026-11-18',
    end: '2026-11-22',
  });

return (

<Stack gap={2} align="start" style={{ width: '100%', maxWidth: '20rem' }}>
<DateRangePicker value={value} onChange={setValue} />
<Text size="sm" tone="muted">
Value: {value ? value.start + ' → ' + value.end : 'none'}
</Text>
</Stack>
);
}`;

<ComponentPreview title="Basic date range picker" code={basicDateRangePickerCode}>
  <DateRangePickerBasicExample />
</ComponentPreview>

The first click sets the start and leaves the span open. Moving the pointer paints the days it would
cover, and the second click commits the range and closes the popover. Clicking an earlier day than the
start swaps the two ends instead of producing an inverted range.

## Range limits

`minDate`, `maxDate`, and `disabledDates` are passed straight to both calendars, so blocked days stay
visible but inert and the navigation stops at the allowed months.

export const boundedRangeCode = `import { useState } from 'react';
import { DateRangePicker } from '@orkest/ui/client';
import type { DateRange } from '@orkest/ui/client';

export function Example() {
  const [value, setValue] = useState<DateRange | null>(null);

return (

<DateRangePicker
value={value}
onChange={setValue}
minDate="2026-11-10"
maxDate="2026-12-20"
disabledDates={(date) => date.endsWith('-15') || date.endsWith('-16')}
style={{ width: '100%', maxWidth: '20rem' }}
/>
);
}`;

<ComponentPreview title="Bounded range" code={boundedRangeCode}>
  <DateRangePickerLimitsExample />
</ComponentPreview>

## One month at a time

`months` defaults to `2`. Set it to `1` when the popover has to stay narrow; the panel also wraps to a
single column by itself when the viewport cannot fit both months side by side.

import { DateRangePicker } from '@orkest/ui/client';
import type { DateRange } from '@orkest/ui/client';

export function Example() {

return (

<DateRangePicker
value={value}
onChange={setValue}
months={1}
style={{ width: '100%', maxWidth: '20rem' }}

## Inside a Field

The trigger reads the surrounding [Field](/docs/components/field/) context: the label points at it and
`aria-describedby` carries the description and validation message.

export const withALabelAndDescriptionCode = `import { useState } from 'react';
import { DateRangePicker, Field, FieldDescription, FieldLabel } from '@orkest/ui/client';
import type { DateRange } from '@orkest/ui/client';

export function Example() {
  const [value, setValue] = useState<DateRange | null>(null);

return (

<Field required style={{ width: '100%', maxWidth: '20rem' }}>
<FieldLabel>Stay</FieldLabel>
<DateRangePicker value={value} onChange={setValue} placeholder="Check in – Check out" />
<FieldDescription>Both ends are submitted with the form.</FieldDescription>
</Field>
);
}`;

<ComponentPreview title="With a label and description" code={withALabelAndDescriptionCode}>
  <DateRangePickerFieldExample />
</ComponentPreview>

Passing `name` renders two hidden inputs, `${name}-start` and `${name}-end`, so a native form submits
both ends without extra wiring.

## Accessibility

- The trigger is a button with `aria-haspopup="dialog"` and `aria-expanded`, so the popup is announced
  before it opens.
- Each month is a grid with a single tab stop and full arrow-key navigation, described in the
  [Calendar documentation](/docs/components/calendar/#accessibility).
- Both endpoints carry `aria-selected`; the days the span covers are painted only, so a screen reader
  hears two selected dates rather than a wall of selected cells.
- The pointer preview is decorative. Keyboard users pick the end date by moving to it and pressing
  `Enter`, which selects the day the focus is on.
