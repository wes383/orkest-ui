title: Empty State
description: A composable placeholder for regions with nothing to show yet.

`EmptyState` explains why a region has nothing in it and, when there is something to do, offers the
next step. It is purely presentational: no data fetching, no state, no extra dependency, and no
Base UI. A single icon is enough for most cases; an illustration is optional.

## Live preview

<ComponentPreview
  title="Basic empty state"
  code={`import { Button, EmptyState } from '@orkest/ui';
import { Inbox } from 'lucide-react';

export function Example() {
  return (
    <EmptyState
      icon={Inbox}
      title="No invoices yet"
      description="Invoices appear here once a customer is billed."
      action={
        <>
          <Button>Create invoice</Button>
          <Button variant="outline">Learn about billing</Button>
        </>
      }
    />
  );
}`}
>
  <EmptyStateBasicExample />
</ComponentPreview>

This is the shorthand API: `title`, `description`, `icon`, `image`, and `action`. Leave out whatever
you do not need. A state with only a sentence is perfectly valid, and every shorthand prop builds the
same parts you can compose by hand.

## Sizes

<ComponentPreview

export function Example() {

          <EmptyState
            size={size}
            title={'No activity (' + size + ')'}
            description="Events will show up here as your team works."
          />
        </Box>
      ))}
    </Stack>
  );
}`}
>
  <EmptyStateSizesExample />
</ComponentPreview>

From top to bottom: `sm`, `md`, `lg`. Size controls how much room the state takes, not what it is:

- `sm` fits a compact region, such as a widget or an empty table body.
- `md` is the default for a normal content area.
- `lg` suits a full-page, first-run state.

Padding, gaps, title size, and the icon surface all scale together. The DOM and the available parts
stay the same, so a size change never forces a different API.

`align="center"` is the default. Use `align="start"` when the surrounding content is left aligned —
for example a panel that already has a left-aligned header. Alignment only changes `align-items` and
`text-align`; the parts and their order are unchanged.

## Composition

When you need several descriptions, more than one action row, a different heading level, or a custom
visual, pass the parts as children. `children` replaces the shorthand content, while `size` and
`align` still style the container.

<ComponentPreview
  title="Custom composition"
  code={`import {
  Button,
  EmptyState,
  EmptyStateAction,
  EmptyStateDescription,
  EmptyStateIcon,
  EmptyStateTitle,
} from '@orkest/ui';
import { Search } from 'lucide-react';

export function Example() {
  return (
    <EmptyState size="lg" align="start">
      <EmptyStateIcon icon={Search} />
      <EmptyStateTitle level={2}>No results for "quarterly report"</EmptyStateTitle>
      <EmptyStateDescription>Check the spelling or try a broader keyword.</EmptyStateDescription>
      <EmptyStateAction>
        <Button>Clear filters</Button>
        <Button variant="outline">Browse all files</Button>
      </EmptyStateAction>
      <EmptyStateDescription>Search also supports file type and date filters.</EmptyStateDescription>
    </EmptyState>
  );
}`}
>
  <EmptyStateCompositionExample />
</ComponentPreview>

There is no limit on how many titles, descriptions, or actions you use. The parts are ordinary
elements:

- `EmptyStateTitle` is a heading, `h3` by default. Set `level` to keep the page outline correct —
  use `2` for a full-page state directly under the `h1`.
- `EmptyStateIcon` accepts a Lucide component through `icon`, or any custom node as children.
- `EmptyStateDescription` is a paragraph you can repeat when the copy needs a second block.
- `EmptyStateAction` is a wrapping flex row; put any number of buttons in it, or omit it entirely.

      style={{

      image={{ src: '/empty-inbox.svg', alt: 'An empty inbox with no documents' }}

      action={<Button variant="outline">Compose a message</Button>}
    />
  );
}`}
>
  <EmptyStateImageExample />
</ComponentPreview>

`EmptyState` draws no border of its own. `className` and `style` pass through to the root, so a
dashed outline is one declaration away — useful when the empty region needs to stand out inside a
larger surface. Leave it off when the parent already frames the content, as in the
[embedding example](#embedding) below.

`image` is optional and takes precedence over `icon` when both are supplied. `alt` is required: it
carries any meaning the illustration adds. If the picture is purely decorative, use `alt=""` and make
sure the title and description say everything on their own. Do not make a custom illustration a
prerequisite for using the component.

## Embedding

`EmptyState` is not built into [Table](/docs/components/table/) or
[Card](/docs/components/card/). It works on its own, and it also drops into whatever region happens
to be empty. This example uses a custom panel with its own header, and also shows a text-only state
with no icon and no action:

<ComponentPreview
  title="Inside a panel"
  code={`import { Box, Button, EmptyState, Separator, Stack, Text } from '@orkest/ui';

export function Example() {
  return (
    <Box background="surface" border radius="xl">
      <Box as="header" padding={4}>
        <Stack direction="row" gap={3} align="center" justify="between">
          <Text weight="semibold">Team members</Text>
          <Button size="sm" variant="outline">
            Invite
          </Button>
        </Stack>
      </Box>
      <Separator />
      <EmptyState
        size="sm"
        title="No members yet"
        description="Invite someone to collaborate in this workspace."
      />
    </Box>
  );
}`}
>
  <EmptyStateEmbeddedExample />
</ComponentPreview>

## Accessibility

- The title is a real heading. Keep the outline in order with `level` when composing; the shorthand
  uses `h3`, which fits a state nested under a section heading.
- The default icon is decorative and hidden from assistive technology. If a custom visual carries
  meaning, give it a name (`label` on `Icon`, or `alt` on an image). An illustration with `alt=""`
  must not be the only explanation of the state.
- Actions are real buttons with visible focus, so keyboard and screen-reader users get the same path
  forward. Do not add click handlers to the container.
- The component deliberately has no `role="status"` or `aria-live`: an empty state is static content,
  not an announcement. If the state appears after a client-side filter change, announce the change on
  the region that owns the content instead.
- Text uses semantic theme colors, so light and dark themes keep their contrast. State is described
  in words, never by color alone.
