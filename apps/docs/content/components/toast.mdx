`Toast` shows brief, non-blocking feedback such as a saved record, a failed request, or a finished
upload. Use it for results the user does not need to confirm. For decisions that require an answer,
use `AlertDialog`; for persistent warnings inside the page, use an inline alert.

The component is built on Base UI Toast and exported from `@orkest/ui/client`.

## Setup

Render one `ToastProvider` and one `ToastViewport` at the application root. The provider connects
the imperative `toast` API to the viewport.

```tsx
import { ToastProvider, ToastViewport } from '@orkest/ui/client';

export function App() {
  return (
    <ToastProvider>
      {/* application */}
      <ToastViewport position="bottom-right" />
    </ToastProvider>
  );
}
```

The imperative API works from event handlers, async functions, and modules outside React.

## Types

| Type | Default icon | Use |
| --- | --- | --- |
| `success` | CircleCheck | The operation succeeded. |
| `error` | CircleX | The operation failed. |
| `warning` | TriangleAlert | The user should pay attention. |
| `info` | Info | Neutral confirmation or status. |
| `loading` | LoaderCircle | Work is still running. Loading toasts never auto-dismiss. |

Only the icon carries the status color; the surface stays neutral in both themes.

## Anatomy

- `ToastProvider` owns the queue, timeout, and limit.
- `ToastViewport` renders the fixed stack and manages the live region.
- `Toast` is one notification root.
- `ToastContent` lays out the icon, text, action, and close button.
- `ToastTitle` and `ToastDescription` render the accessible title and description.
- `ToastAction` adds one optional action such as Undo.
- `ToastClose` dismisses the toast.
- `ToastIcon` derives its icon from the toast type.

## Promise tracking

`toast.promise` creates a loading toast and updates it in place when the promise settles.

<ComponentPreview
  title="Upload state"
  code={`import { Button } from '@orkest/ui';
import { toast } from '@orkest/ui/client';

function simulateUpload() {
  return new Promise<void>((resolve) => {
    window.setTimeout(resolve, 1600);
  });
}

export function Example() {
  return (
    <Button
      onClick={() =>
        toast.promise(simulateUpload(), {
          loading: 'Uploading file…',
          success: 'Upload complete',
          error: 'Upload failed',
        })
      }
    >
      Upload file
    </Button>
  );
}`}

## Managing toasts

```tsx
const id = toast.show({ title: 'Saving…', type: 'loading' });

toast.update(id, { title: 'Saved', type: 'success', duration: 4000 });

toast.dismiss(id); // close one toast
toast.dismissAll(); // close every toast
```

Adding a toast with an existing `id` updates it instead of creating a duplicate. `duration={0}`
keeps a toast open until it is closed.

## Queue and limit

`ToastProvider` shows at most `limit` toasts (default `3`) and keeps older ones inert. `timeout`
sets the default auto-dismiss delay in milliseconds (default `5000`).

<ComponentPreview
  title="Limited queue"
  code={`import { useState } from 'react';
import { Button, Stack } from '@orkest/ui';
import {
  createToast,
  ToastProvider,
  ToastViewport,
} from '@orkest/ui/client';

export function Example() {
  const [host] = useState(() => createToast());
  const [count, setCount] = useState(0);

  return (
    <ToastProvider toastManager={host.manager} limit={2}>
      <Stack direction="row" gap={2} wrap>
        <Button
          variant="outline"
          onClick={() => {
            const next = count + 1;
            setCount(next);
            host.toast.info('Notification ' + next);
          }}
        >
          Add notification
        </Button>
        <Button variant="ghost" onClick={() => host.toast.dismissAll()}>
          Dismiss all
        </Button>
      </Stack>
      <ToastViewport position="bottom-left" />
    </ToastProvider>
  );
}`}
>
  <ToastQueueExample />
</ComponentPreview>

Hovering the viewport or focusing it with the keyboard pauses the timers. Press `F6` to move focus
into the toast region and `F6` again to return to the previous element.

## Custom rendering

Pass a render function to `ToastViewport` to replace the default item. Keep `Toast` as the root so
swipe behavior and timers stay intact.

```tsx
<ToastViewport position="bottom-right">
  {(toastObject) => (
    <Toast toast={toastObject}>
      <ToastContent>
        <ToastIcon />
        <div>
          <ToastTitle />
          <ToastDescription />
        </div>
        <ToastAction />
        <ToastClose />
      </ToastContent>
    </Toast>
  )}
</ToastViewport>
```

## Accessibility

- The viewport is a labelled `region` with `aria-live="polite"`.
- Toasts use `role="dialog"` by default; `priority: 'high'` uses an alert announcement.
- Toasts never steal focus. `F6` moves focus into the region on demand.
- The close button has the accessible name `Close notification` by default. Override it with
  `label` on `ToastClose`.
- Actions are real buttons and are reachable with the keyboard.
- Status is conveyed by an icon shape and text, not by color alone.
- Motion respects `prefers-reduced-motion`; swipe-to-dismiss remains available.
