`DataTable` layers behaviour over the presentational [Table](/docs/components/table/): column
definitions, sorting, global search, pagination, row selection, row expansion, and column
visibility. All of it runs on the client against the data you pass in — no fetching, no caching, and
no data source assumptions. Table styling (`variant`, `size`, `striped`, `hoverable`) passes straight
through. Import the component and the `DataColumn` type from `@orkest/ui/client`.

## Live preview

export const invoiceTableCode = `import { DataTable, type DataColumn } from '@orkest/ui/client';

interface Invoice {
  id: string;
  customer: string;
  amount: number;
}

const invoices: Invoice[] = [
  { id: 'INV-1042', customer: 'Northwind', amount: 2400 },
  { id: 'INV-1043', customer: 'Contoso', amount: 980 },
];

const columns: DataColumn<Invoice>[] = [
  { id: 'customer', header: 'Customer', accessor: (row) => row.customer, minWidth: 160 },
  {
    id: 'amount',
    header: 'Amount',
    accessor: (row) => row.amount,
    align: 'right',
    cell: (row) => row.amount.toFixed(2),
  },
];

export function Example() {
  return <DataTable columns={columns} data={invoices} getRowId={(row) => row.id} caption="Invoices" />;
}`;

## Columns

Columns are plain objects. `accessor` feeds sorting and search; `cell` decides what is rendered.

```tsx
import { Badge } from '@orkest/ui';
import { DataTable, type DataColumn } from '@orkest/ui/client';

interface Invoice {
  id: string;
  customer: string;
  amount: number;
  status: 'Paid' | 'Pending';
}

const columns: DataColumn<Invoice>[] = [
  { id: 'customer', header: 'Customer', accessor: (row) => row.customer, minWidth: 160 },
  {
    id: 'amount',
    header: 'Amount',
    accessor: (row) => row.amount,
    align: 'right',
    cell: (row) => row.amount.toFixed(2),
  },
  {
    id: 'status',
    header: 'Status',
    accessor: (row) => row.status,
    cell: (row) => <Badge>{row.status}</Badge>,
  },
];

<DataTable columns={columns} data={invoices} getRowId={(row) => row.id} caption="Invoices" />;
```

- `id` must be stable: it keys sorting, visibility, and selection.
- `accessor` returns the sortable, searchable value. Keep it free of formatting — formatting belongs
  in `cell`.
- `sortable={false}` and `searchable={false}` opt a single column out.

## Sorting

Clicking a sortable header cycles ascending → descending → unsorted. Sorting is single-column, and
numbers compare numerically while everything else compares as text with numeric awareness, so
`Item 2` sorts before `Item 10`. The active direction is exposed through `aria-sort` on the header
cell.

## Search

The toolbar input filters rows whose searchable columns contain the query, case-insensitively. Search
runs before sorting and pagination, and changing it resets the table to the first page.

## Pagination

`pageSize` defaults to `10`. The footer pairs a live range summary with the
[Pagination](/docs/components/pagination/) control, so long result sets get page numbers instead of a
single step button. When search or a data change shrinks the result set, the table clamps to the last
valid page instead of showing an empty one.

## Selection

export const rowSelectionCode = `import { useState } from 'react';
import { DataTable, type DataColumn } from '@orkest/ui/client';

const rows = [
  { id: 'INV-1042', customer: 'Northwind' },
  { id: 'INV-1043', customer: 'Contoso' },
];

const columns: DataColumn<(typeof rows)[number]>[] = [
  { id: 'customer', header: 'Customer', accessor: (row) => row.customer },
];

export function Example() {
  const [selected, setSelected] = useState<typeof rows>([]);

  return (
    <DataTable
      columns={columns}
      data={rows}
      caption="Invoices"
      selectable
      variant="bordered"
      paginated={false}
      getRowId={(row) => row.id}
      onSelectionChange={setSelected}
    />
  );
}`;

<ComponentPreview
  title="Row selection"

>

</ComponentPreview>

Selecting is opt-in with `selectable`. The header checkbox covers the rows on the current page, not
the whole data set — a predictable scope when results span several pages. `onSelectionChange`
receives the selected rows, so the caller owns what happens next. The example above also uses
`variant="bordered"` for the framed cell treatment.

`expandable` adds a toggle column and renders `renderExpanded(row)` in an extra row underneath.
Only the toggle button carries `aria-expanded`, so the extra row never joins the row count that
assistive technology announces for the table body.

## Column visibility

The Columns menu toggles individual columns and keeps the menu open while you work. Hidden columns
keep their state; nothing about sorting or selection is lost when a column is hidden and restored.

## Row actions

Row actions are an ordinary column whose `cell` renders a menu. `DropdownMenu` portals its content,
so the menu escapes the table's horizontal scroll container instead of being clipped by a cell.

export const rowActionsColumnCode = `import { Ellipsis, Pencil, Trash2 } from 'lucide-react';
import { IconButton } from '@orkest/ui';
import {
  DataTable,
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuItem,
  DropdownMenuPortal,
  DropdownMenuTrigger,
  type DataColumn,
} from '@orkest/ui/client';

const rows = [
  { id: 'INV-1042', customer: 'Northwind' },
  { id: 'INV-1043', customer: 'Contoso' },
];

const columns: DataColumn<(typeof rows)[number]>[] = [
  { id: 'customer', header: 'Customer', accessor: (row) => row.customer },
  {
    id: 'actions',
    header: 'Actions',
    accessor: () => null,
    sortable: false,
    searchable: false,
    align: 'right',
    cell: (row) => (
      <DropdownMenu>
        <DropdownMenuTrigger
          render={
            <IconButton icon={Ellipsis} label={'Actions for ' + row.id} size="sm" variant="ghost" />
          }
        />
        <DropdownMenuPortal>
          <DropdownMenuContent align="end">
            <DropdownMenuItem leftIcon={Pencil}>Edit invoice</DropdownMenuItem>
            <DropdownMenuItem leftIcon={Trash2}>Delete</DropdownMenuItem>
          </DropdownMenuContent>
        </DropdownMenuPortal>
      </DropdownMenu>
    ),
  },
];

export function Example() {
  return <DataTable columns={columns} data={rows} caption="Invoices" paginated={false} />;
}`;

<ComponentPreview
  title="Row actions column"
  code={rowActionsColumnCode}
>
  <DataTableActionsExample />
</ComponentPreview>

Three details matter: `sortable` and `searchable` are off because the column has no value to sort or
search, `align="right"` keeps the trigger next to the row edge, and the trigger carries a per-row
accessible name so it is not announced as a nameless button. The same pattern works with a plain
[Table](/docs/components/table/): render the menu inside a `TableCell`.

## Narrow screens

The table scrolls horizontally inside its own container. Header cells never wrap, which means a
table with many columns starts scrolling as soon as the headers exceed the available width. Body
cells do wrap by default, so a table whose headers are short but whose content is long will
compress instead of scrolling — give those columns a `minWidth` to keep them readable and let the
container scroll.

export const wideTableWithHorizontalScrollCode = `import { DataTable, type DataColumn } from '@orkest/ui/client';

const rows = [
  { id: 'INV-1042', customer: 'Northwind', email: 'billing@northwind.example', region: 'EMEA' },
];

const columns: DataColumn<(typeof rows)[number]>[] = [
  { id: 'id', header: 'Invoice', accessor: (row) => row.id, minWidth: 110 },
  { id: 'customer', header: 'Customer', accessor: (row) => row.customer, minWidth: 170 },
  { id: 'email', header: 'Billing email', accessor: (row) => row.email, minWidth: 220 },
  { id: 'region', header: 'Region', accessor: (row) => row.region, minWidth: 120 },
  // …more columns with explicit minWidth
];

export function Example() {
  return <DataTable columns={columns} data={rows} caption="Invoices" pageSize={5} size="sm" />;
}`;

## Accessibility

- The table is a real `table` with real header cells. Pass `caption` so it has an accessible name; it
  is hidden visually but stays available to assistive technology.
- Sortable headers are `button` elements inside the header cell, so they are keyboard reachable.
  `aria-sort` reports the current direction.
- Selection checkboxes carry labels: one for the page-level toggle and one per row.
- The range summary is a polite live region, so page changes are announced without moving focus.
- Search results replace the body in place. Keep the table inside a region with a heading so the
  change of content has context.
