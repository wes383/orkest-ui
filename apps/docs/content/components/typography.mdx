Orkest UI provides a small typography family built on the `Text` primitive. Each component renders
the correct native element by default and shares the same size, weight, color, alignment, spacing,
and overflow options.

Use these components instead of styling headings and paragraphs ad hoc. For the underlying font
tokens, see [Typography foundations](/docs/foundations/typography/).

## Heading levels

`level` sets both the rendered heading element and the default size. Level 1 renders an `h1` at the
`5xl` size; the preview below starts at level 2 because the documentation page already owns its `h1`.

Use `as` when the visual level and the document structure need to differ, and `size` to override the
visual size without changing semantics.

## Text sizes

The full type scale is available on `Text` and all semantic text components. `inherit` keeps the
surrounding size, which is useful for inline elements such as `Strong`, `Code`, and `Link`.

## Overflow

`truncate` limits text to one line. `lineClamp` limits it to a number of lines and takes precedence
when both props are set. Both options are visual; the full text remains in the DOM.

<ComponentPreview
  title="Single-line and multi-line overflow"
  code={`import { Box, Stack, Text } from '@orkest/ui';

export function Example() {
  return (
    <Box style={{ width: '22rem' }}>
      <Stack gap={2}>
        <Text as="p" truncate>
          Single-line truncation keeps long copy from wrapping onto a second line.
        </Text>
        <Text as="p" lineClamp={2}>
          Multi-line clamping stops after two lines and hides the remainder, which is useful for
          previews, cards, and feed summaries.
        </Text>
      </Stack>
    </Box>
  );
}`}

## Component defaults

- `Heading` renders `h1`–`h6` from `level` (default `2`) with a level-driven size, semibold weight,
  tight line height, and tighter tracking.
- `Paragraph` renders `p` at `md` with relaxed line height.
- `Label` renders `label` at `sm` with medium weight.
- `Caption` renders `span` at `xs` with the muted tone.
- `Small` renders `small` at `sm` and inherits the surrounding color.
- `Strong` renders `strong` at `inherit` size with semibold weight and inherited color.
- `Code` renders `code` at `inherit` size with the monospace face and a subtle token surface.
- `Link` renders `a` at `inherit` size with the accent tone and a persistent underline.

## Accessibility

- `Heading` renders a real heading element. Do not skip levels. Use `size` and `as` only when the
  visual design or page structure requires decoupling.
- `Paragraph`, `Label`, `Strong`, `Code`, and `Link` render `p`, `label`, `strong`, `code`, and `a`.
  Keep those semantics unless a different element is genuinely correct.
- Associate `Label` with its control through `htmlFor` or by wrapping the control.
- `Link` is for navigation. Use `Button` for actions, including `variant="link"`.
- Links use color and an underline, so meaning is not communicated by color alone.
- Truncation and line clamping are visual. The full text stays in the DOM; provide a title or another
  way to read critical content when necessary.
- `tone` is semantic color, not a replacement for context. Pair status tones with text or an icon.
