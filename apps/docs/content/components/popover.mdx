`Popover` displays interactive content near a trigger. Use it for filters, forms, settings, inline
help, and other content that needs more room than a tooltip.

The component is built on Base UI Popover and exported from `@orkest/ui/client`.

## Basic usage

export const filterPopoverCode = `import { Stack } from '@orkest/ui';
import {
  Field,
  FieldLabel,
  Input,
  Popover,
  PopoverClose,
  PopoverContent,
  PopoverDescription,
  PopoverPortal,
  PopoverPositioner,
  PopoverTitle,
  PopoverTrigger,
} from '@orkest/ui/client';

export function Example() {
  return (
    <Popover>
      <PopoverTrigger>Open filters</PopoverTrigger>
      <PopoverPortal>
        <PopoverPositioner>
          <PopoverContent width="20rem">
            <Stack gap={3}>
              <Stack gap={1}>
                <PopoverTitle>Filters</PopoverTitle>
                <PopoverDescription>
                  Narrow the result list without leaving the page.
                </PopoverDescription>
              </Stack>
              <Field>
                <FieldLabel>Search</FieldLabel>
                <Input placeholder="Project name" />
              </Field>
              <PopoverClose>Done</PopoverClose>
            </Stack>
          </PopoverContent>
        </PopoverPositioner>
      </PopoverPortal>
    </Popover>
  );
}`;

## Anatomy

- `Popover` owns the open state.
- `PopoverTrigger` toggles the popover. It renders a secondary Button by default.
- `PopoverPortal` moves the popover to the document body.
- `PopoverPositioner` positions the content and handles viewport collisions.
- `PopoverContent` is the interactive surface. Its children scroll inside the surface.
- `PopoverArrow` adds an optional arrow. Keep it as a direct child of `PopoverContent` so it stays
  outside the scrollable body and animates with the surface.
- `PopoverTitle` and `PopoverDescription` provide the accessible name and description.
- `PopoverClose` closes the popover and renders a secondary Button by default.

## Positioning and arrow

`PopoverPositioner` defaults to `side="bottom"`, `align="center"`, and `sideOffset={8}`. Override the
side, alignment, and offsets when the trigger needs a different layout.

export const rightAlignedPopoverCode = `import { Stack } from '@orkest/ui';
import {
  Popover,
  PopoverArrow,
  PopoverContent,
  PopoverDescription,
  PopoverPortal,
  PopoverPositioner,
  PopoverTitle,
  PopoverTrigger,
} from '@orkest/ui/client';

export function Example() {
  return (
    <Popover>
      <PopoverTrigger variant="outline">Open on the right</PopoverTrigger>
      <PopoverPortal>
        <PopoverPositioner side="right" align="start" sideOffset={12}>
          <PopoverContent maxWidth="18rem">
            <PopoverArrow />
            <Stack gap={2}>
              <PopoverTitle>Positioned content</PopoverTitle>
              <PopoverDescription>
                This popover prefers the right side and aligns to the trigger start.
              </PopoverDescription>
            </Stack>
          </PopoverContent>
        </PopoverPositioner>
      </PopoverPortal>
    </Popover>
  );
}`;

## Controlled state

export const controlledPopoverCode = `import { useState } from 'react';
import { Stack, Text } from '@orkest/ui';
import {
  Popover,
  PopoverClose,
  PopoverContent,
  PopoverDescription,
  PopoverPortal,
  PopoverPositioner,
  PopoverTitle,
  PopoverTrigger,
} from '@orkest/ui/client';

export function Example() {
  const [open, setOpen] = useState(false);

  return (
    <Stack direction="row" gap={3} wrap align="center">
      <Popover open={open} onOpenChange={setOpen}>
        <PopoverTrigger>Toggle popover</PopoverTrigger>
        <PopoverPortal>
          <PopoverPositioner>
            <PopoverContent maxWidth="18rem">
              <Stack gap={2}>
                <PopoverTitle>Controlled popover</PopoverTitle>
                <PopoverDescription>The parent owns the open state.</PopoverDescription>
                <PopoverClose>Close</PopoverClose>
              </Stack>
            </PopoverContent>
          </PopoverPositioner>
        </PopoverPortal>
      </Popover>
      <Text size="sm" tone="muted">
        {open ? 'Status: open' : 'Status: closed'}
      </Text>
    </Stack>
  );
}`;

## Dialog semantics

`PopoverContent` renders `role="dialog"` by default and uses `PopoverTitle` and
`PopoverDescription` for `aria-labelledby` and `aria-describedby`. When the content is not a dialog,
pass a different role such as `region` or `group`:

```tsx
<PopoverContent role="region">{/* ... */}</PopoverContent>
```

Use dialog semantics when the content has a clear title and behaves like a small dialog. Use a
region or group for lightweight inline help.

## Sizing and scrolling

`PopoverContent` fits its content by default, has a maximum width of `25rem`, and scrolls when it
exceeds the available viewport height. Use `width`, `minWidth`, `maxWidth`, and `maxHeight` for
specific layouts.

export const regionSemanticsCode = `import { Stack, Text } from '@orkest/ui';
import {
  Popover,
  PopoverClose,
  PopoverContent,
  PopoverPortal,
  PopoverPositioner,
  PopoverTrigger,
} from '@orkest/ui/client';

export function Example() {
  return (
    <Popover>
      <PopoverTrigger variant="outline">Show inline help</PopoverTrigger>
      <PopoverPortal>
        <PopoverPositioner>
          <PopoverContent role="region" maxWidth="18rem">
            <Stack gap={2}>
              <Text size="sm" weight="medium">
                Keyboard shortcuts
              </Text>
              <Text as="p" size="sm" tone="muted">
                Press ⌘K to search. Use arrow keys to move between results.
              </Text>
              <PopoverClose>Got it</PopoverClose>
            </Stack>
          </PopoverContent>
        </PopoverPositioner>
      </PopoverPortal>
    </Popover>
  );
}`;

## Accessibility

- `PopoverTrigger` should have a clear accessible name. The default Button uses its children.
- Focus moves into the content when the popover opens and returns to the trigger when it closes.
- Escape and outside pointer presses close the popover by default.
- Use `PopoverTitle` for the accessible name and `PopoverDescription` for supporting text.
- Use dialog semantics for dialog-like content and a region or group for lightweight content.
- `PopoverContent` can contain forms, buttons, and other interactive components.
- The arrow is decorative and does not affect the accessible name.
- The popover respects `prefers-reduced-motion` for its open and close animation.
