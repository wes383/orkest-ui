`Select` is a single-value combobox built on a native button or text input and a custom listbox. It
renders selected values, supports keyboard navigation, and positions the menu with viewport
collision handling.

Import it from `@orkest/ui/client` because the menu uses client-side state and positioning.

## Searchable

Set `searchable` to turn the trigger into a text input. Typing filters option labels with a
case-insensitive match; clear the query to restore the full list. Pass `filterOption` to replace the
default matcher, or `onSearchChange` together with `loading` for async search.

<ComponentPreview
  title="Searchable select"
  code={`import { Select } from '@orkest/ui/client';

export function Example() {
  return (
    <Select
      aria-label="Team"
      options={options}
      searchable
      searchPlaceholder="Search teams"
      placeholder="Choose a team"
    />
  );
}`}
>
  <SearchableSelectExample />
</ComponentPreview>

For async search, return `true` from `filterOption` when the server already filtered the options:

```tsx
<Select
  searchable
  options={results}
  loading={loading}
  filterOption={() => true}
  onSearchChange={(query) => fetchOptions(query)}
/>
```

## Groups, descriptions, and icons

Options can be grouped and extended with `description`, `icon`, and `disabled`:

```ts
interface SelectOption {
  value: string;
  label: string;
  description?: ReactNode;
  icon?: LucideIcon;
  disabled?: boolean;
}

interface SelectOptionGroup {
  label: string;
  options: SelectOption[];
}
```

Groups render `role="group"` with the group label as the accessible name. Descriptions are visible
secondary text and are included in the option's accessible name.

`disabled` blocks interaction, `invalid` applies the danger border and `aria-invalid`, and
`clearable` adds a clear action while a value is selected.

## Accessibility

- The trigger renders `role="combobox"` with `aria-expanded`, `aria-controls`, and
  `aria-haspopup="listbox"`. The popup renders `role="listbox"` and each item `role="option"` with
  `aria-selected` and `aria-disabled`.
- The active option is tracked with `aria-activedescendant`; focus stays on the combobox.
- The menu is positioned below the trigger and flips or shifts to stay inside the viewport. It is
  rendered inside the component root, so scoped themes apply.
- Outside pointer interactions close the menu. Selecting an option closes it and restores focus.
- Disabled options are skipped by arrow keys and typeahead.
- `required` sets `aria-required` and the `name` prop renders a hidden input. Because this is a custom
  combobox, browsers do not run native constraint validation; validate in the form submit handler.
- Associate a visible label with `id` and `htmlFor`, or use `aria-label` / `aria-labelledby`.

| Key | Behavior |
| --- | --- |
| `Enter` / `Space` | Opens the menu or selects the active option |
| `ArrowDown` / `ArrowUp` | Moves the active option |
| `Home` / `End` | Moves to the first or last enabled option |
| `Escape` | Closes the menu and restores focus |
| `Tab` | Closes the menu and moves focus |
| Letter keys | Typeahead when closed or not searchable; filters when searchable |
