`Grid` provides two-dimensional layout with shared spacing tokens and responsive column values.
Responsive rules use CSS media queries, so rendering does not depend on JavaScript viewport
measurements.

## Native templates

Pass any valid `grid-template-columns` value when a fixed count is not enough. The example below
uses `auto-fit` so the grid fills the available width without breakpoints.

## Gaps and alignment

`columnGap` and `rowGap` override `gap` for one axis. `align` and `justify` map to `align-items` and
`justify-items`.

## Responsive values

`columns`, `rows`, `gap`, `columnGap`, and `rowGap` accept an object with `base`, `sm`, `md`, `lg`,
and `xl` keys. Values carry forward to larger breakpoints.

```tsx
<Grid columns={{ base: 1, sm: 2, lg: 3 }} gap={{ base: 2, lg: 6 }}>
  {/* items */}
</Grid>
```

| Key | Media query |
| --- | --- |
| `base` | No media query |
| `sm` | `min-width: 40rem` (640px) |
| `md` | `min-width: 48rem` (768px) |
| `lg` | `min-width: 64rem` (1024px) |
| `xl` | `min-width: 80rem` (1280px) |

## Accessibility

- `Grid` changes visual layout only. It adds no ARIA roles or keyboard behavior.
- Reading order remains DOM order. Avoid visual reordering that contradicts the source order.
- `autoFlow="dense"` can move items visually; use it only when the content order does not carry
  meaning.
- Use `as` to render semantic elements such as `section`, `ul`, or `nav` when appropriate.
- Responsive behavior is CSS-only. There are no resize listeners and no client-side viewport reads.
