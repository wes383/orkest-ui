`Field` groups a label, form control, description, and message into one accessible unit. It is built
on Base UI Field, so validation state, disabled state, and ARIA relationships stay in sync.

`Field` and its parts are exported from `@orkest/ui/client`. Render them inside a Client Component.

## Basic usage

export const labelInputAndDescriptionCode = `import { Box } from '@orkest/ui';
import { Field, FieldDescription, FieldLabel, Input } from '@orkest/ui/client';

export function Example() {
  return (
    <Box width="100%" maxWidth="22rem">
      <Field>
        <FieldLabel>Email</FieldLabel>
        <Input type="email" placeholder="you@example.com" />
        <FieldDescription>We only use this for account notices.</FieldDescription>
      </Field>
    </Box>
  );
}`;

<ComponentPreview title="Label, input, and description" code={labelInputAndDescriptionCode}>
  <FieldBasicExample />
</ComponentPreview>

`FieldLabel`, `FieldDescription`, and `FieldMessage` connect to the control automatically through
`aria-labelledby` and `aria-describedby`. Custom controls such as Checkbox and Switch receive the
label through `aria-labelledby`; pass `htmlFor` explicitly when you need native label-click behavior
for a custom control.

## Required and optional

Set `required` on `Field` to require the control and show the required indicator. The indicator
keeps the visual asterisk separate from a screen-reader “Required” label, so the state is not
communicated by color alone.

export const requiredAndOptionalFieldsCode = `import { Box, Stack } from '@orkest/ui';
import { Field, FieldLabel, Input } from '@orkest/ui/client';

export function Example() {
  return (
    <Box width="100%" maxWidth="22rem">
      <Stack gap={4}>
        <Field required>
          <FieldLabel>Full name</FieldLabel>
          <Input placeholder="Ada Lovelace" />
        </Field>
        <Field>
          <FieldLabel optional>Job title</FieldLabel>
          <Input placeholder="Engineer" />
        </Field>
      </Stack>
    </Box>
  );
}`;

</ComponentPreview>

## Validation

`validate` and `validationMode` are delegated to Base UI Field. When the control participates in
the field, `FieldMessage` shows the validation message automatically and hides it again once the
field becomes valid.

export const validationOnChangeCode = `import { Box } from '@orkest/ui';
import { Field, FieldDescription, FieldLabel, FieldMessage, Input } from '@orkest/ui/client';

export function Example() {
  return (
    <Box width="100%" maxWidth="22rem">
      <Field
        validate={(value) => (value === 'admin' ? 'This workspace name is reserved.' : null)}
        validationMode="onChange"
      >
        <FieldLabel>Workspace URL</FieldLabel>
        <Input placeholder="acme" />
        <FieldDescription>Try typing admin to see validation.</FieldDescription>
        <FieldMessage icon />
      </Field>
    </Box>
  );
}`;

<ComponentPreview title="Validation on change" code={validationOnChangeCode}>
  <FieldValidationExample />
</ComponentPreview>

The same pattern works with `Select` and `Textarea`, which also register with Base UI Field. Type
`admin` in the example above to see the error appear and then disappear.

## Messages

`FieldMessage` handles error, success, warning, and info tones. Error messages are announced with
`role="alert"`; the other tones use `role="status"`.

export const messageTonesCode = `import { Box, Stack } from '@orkest/ui';
import { Field, FieldLabel, FieldMessage, Input } from '@orkest/ui/client';

export function Example() {
  return (
    <Box width="100%" maxWidth="22rem">
      <Stack gap={4}>
        <Field>
          <FieldLabel>API key</FieldLabel>
          <Input defaultValue="ok_live_9f2c" />
          <FieldMessage type="success" icon>
            Your key is active.
          </FieldMessage>
        </Field>
        <Field>
          <FieldLabel>Storage</FieldLabel>
          <Input defaultValue="8.4 GB" />
          <FieldMessage type="warning" icon>
            You are close to your quota.
          </FieldMessage>
        </Field>
        <Field>
          <FieldLabel>Region</FieldLabel>
          <Input defaultValue="eu-west-1" />
          <FieldMessage type="info" icon>
            Data stays in the EU.
          </FieldMessage>
        </Field>
      </Stack>
    </Box>
  );
}`;

<ComponentPreview title="Message tones" code={messageTonesCode}>
  <FieldMessagesExample />
</ComponentPreview>

Error messages are only shown while the field is invalid and enabled. Render one message per field;
descriptions and messages are appended to `aria-describedby` in registration order.

## Composing with controls

Controls that render their own label should use that label instead of `FieldLabel`. The field still
links descriptions, messages, names, disabled state, and required state.

export const checkboxWithHelpTextCode = `import { Box } from '@orkest/ui';
import { Checkbox, Field, FieldDescription, FieldMessage } from '@orkest/ui/client';

export function Example() {
  return (
    <Box width="100%" maxWidth="22rem">
      <Field>
        <Checkbox label="Product updates" defaultChecked />
        <FieldDescription>At most one email per month.</FieldDescription>
        <FieldMessage type="info">You can unsubscribe at any time.</FieldMessage>
      </Field>
    </Box>
  );
}`;

<ComponentPreview title="Checkbox with help text" code={checkboxWithHelpTextCode}>
  <FieldCheckboxExample />
</ComponentPreview>

export const selectWithAFieldLabelCode = `import { Box } from '@orkest/ui';
import { Field, FieldDescription, FieldLabel, Select } from '@orkest/ui/client';

export function Example() {
  return (
    <Box width="100%" maxWidth="22rem">
      <Field>
        <FieldLabel>Country</FieldLabel>
        <Select
          options={[
            { value: 'us', label: 'United States' },
            { value: 'ca', label: 'Canada' },
            { value: 'gb', label: 'United Kingdom' },
          ]}
        />
        <FieldDescription>Used to calculate tax.</FieldDescription>
      </Field>
    </Box>
  );
}`;

<ComponentPreview title="Select with a field label" code={selectWithAFieldLabelCode}>
  <FieldSelectExample />
</ComponentPreview>

For radio groups, prefer `Fieldset` and `Legend`. A `FieldLabel` inside `Field` also names the group
through `aria-labelledby`.

## Accessibility

- `FieldLabel` is connected to the control for `htmlFor` and `aria-labelledby`; custom controls such
  as Checkbox and Switch receive `aria-labelledby`. Pass `htmlFor` explicitly when a custom control
  needs native label-click behavior.
- Descriptions and messages are added to `aria-describedby`. Multiple ids are supported.
- Invalid fields set `aria-invalid` on the control. Error messages use `role="alert"`; success,
  warning, and info messages use `role="status"`.
- Required fields set the native `required` attribute and include screen-reader text in the label.
- `Fieldset` uses a native `<fieldset>` with a native `<legend>`, so the group has an accessible
  name and shared disabled state.
- Disabled state uses native attributes and muted text, not color alone.
- The horizontal layout keeps the same reading and focus order as the stacked layout: label,
  control, description, message.
