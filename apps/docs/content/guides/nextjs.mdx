Orkest UI can be used in the Next.js App Router. The main integration points are the compiled
stylesheet, the theme attribute, and the font files loaded by the host application.

## Import styles once

Import the package stylesheet in the root layout:

```tsx
import '@orkest/ui/style.css';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

## Set the theme before paint

Add the theme attribute script from the [Theming guide](/docs/guides/theming/) at the start of the
body, and set `suppressHydrationWarning` on the `<html>` element:

```tsx
<html lang="en" suppressHydrationWarning>
  <body>
    <ThemeScript />
    {children}
  </body>
</html>
```

## Load fonts

The library references Inter, Plus Jakarta Sans, JetBrains Mono, and a Noto Sans CJK fallback. Load
those fonts in the host application. The documentation app uses the `@fontsource-variable` packages:

```ts
import '@fontsource-variable/inter';
import '@fontsource-variable/plus-jakarta-sans';
import '@fontsource-variable/jetbrains-mono';
```

## Server and client components

Components exported from `@orkest/ui` are server-safe. They do not fetch data, so App Router pages
can render them directly.

Components exported from `@orkest/ui/client` keep client-side state: form controls, `Select`,
`MultiSelect`, `Tabs`, `Dialog`, `AlertDialog`, `DropdownMenu`, `Popover`, `Tooltip`, `Toast`,
`Alert`, `Avatar`, and the `Field` parts. Import them from `@orkest/ui/client` inside a Client
Component (a module with `'use client'`).

Wrap tooltips in `TooltipProvider` to share the hover delay across a subtree.

## Verify the integration

- The page renders with the expected theme.
- The stylesheet is loaded exactly once.
- Fonts resolve to Inter, JetBrains Mono, and the CJK fallback.
- No hydration warning appears in the console.
