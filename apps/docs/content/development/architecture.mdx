Orkest UI is a pnpm workspace with two applications:

```text
orkest-ui/
├── apps/
│   └── docs/          Next.js documentation website
├── packages/
│   └── ui/            @orkest/ui component library
├── pnpm-workspace.yaml
└── package.json
```

## UI package

`packages/ui` contains the library source:

```text
src/
├── primitives/
│   ├── box/
│   ├── icon/
│   ├── stack/
│   └── text/
├── styles/
│   ├── tokens.css
│   ├── themes.css
│   ├── base.css
│   └── index.css
├── test/setup.ts
├── utils/cx.ts
└── index.ts
```

Each primitive owns its implementation, CSS Module, tests, and barrel export. `src/index.ts` is the
only public entry point.

The build uses Vite library mode and emits:

- `dist/index.js` as ESM.
- `dist/style.css` with tokens, themes, and component styles.
- `dist/index.d.ts` with bundled public types.

React and React DOM are peer dependencies. `lucide-react` is a regular dependency.

## Documentation app

`apps/docs` is a Next.js App Router application. It consumes the built `@orkest/ui` package rather
than importing library source directly:

- MDX content lives in `content/`.
- Documentation UI lives in `components/`.
- Content loading, navigation, search, token parsing, and MDX compilation live in `lib/`.
- The app loads `@orkest/ui/style.css` in the root layout.

Because the package exports `dist`, the docs `dev`, `build`, and `typecheck` scripts build
`packages/ui` first.

## Root scripts

```bash
pnpm build          # Build packages/ui
pnpm test           # Run library tests
pnpm typecheck      # Type check every workspace package
pnpm docs           # Start the documentation app
pnpm build:docs     # Build the static documentation site
```

## Source of truth

- Component behavior and public API: `packages/ui/src`.
- Token names and values: `packages/ui/src/styles`.
- Explanatory content: `apps/docs/content`.

The documentation reads token values from the source stylesheets at build time. It does not maintain
a second copy of the palette or spacing scale.
